# UI·인터페이스·재미 요소 점검

2026-09-09 운영 사이트 https://aram4.vercel.app 점검. 데이터 동기화, DB, 점수 모델 변경은 범위에서 제외한다. 최초 리뷰 후 사용자의 전체 진행 요청에 따라 아래 개선을 구현했다.

## 구현 및 검증

- 모바일 프로필·경기 카드, 의미별 색상, 한국어·KST 표기를 통일했다.
- 홈의 첫 경기 목록은 동일한 390px 화면과 6경기 기준으로 1,838px → 670px로 올라왔다.
- 날짜·펼친 경기 URL 보존과 복귀를 확인했다. 서로 다른 날짜의 경기에서 돌아오면 원래 선택 날짜의 목록으로 이동한다.
- 전적 영수증 PNG 생성·다운로드, 날짜 링크 복사, 시상식 수동 재생·닫기 및 자동 연출 설정을 구현했다.
- 주간·월간·전체 타이틀 경쟁, 도전자 격차, 공동 1위, 메달 현황, 역할별 기록을 묶었다.
- 개인 최고점·최다 어시 경신 및 반등 카드에 현재·이전 경기 링크를 연결했다.
- 네 명의 개인 페이지에 인터랙티브 폼 그래프와 챔피언 도감을 적용했다. 검색·정렬·최소 경기 수·점수 구간·미도전 및 최고점·첫 승을 지원한다.
- 메달 수상 수치와 실제 판정 기준을 펼쳐 볼 수 있다. 해설은 관측하지 않은 한타·포킹 원인 대신 저장된 지표를 설명한다.
- 테스트 100개, TypeScript 프로덕션 빌드, 린트 검증을 수행했다. 브라우저에서 360/390px 및 데스크톱, 네 명의 개인 페이지, 날짜 복귀, PNG 다운로드, 시상식 Escape 닫기, 빈 날짜를 점검했다.
- 검토 당시 이용 가능한 기록은 227경기였다. 전체·최고·첫 승은 조회한 기록(최대 500경기) 기준으로 안내한다. 실제 휴대폰 Safari 검증은 포함하지 않는다.

## 점검 범위와 근거

- 실제 Chrome headless에서 데스크톱 1440×1000, 모바일 390×844 확인. 홈은 360px 폭도 추가 확인.
- 홈, 최신 경기 상세, 네 명의 개인 페이지, 경기 펼치기, 이전 날짜 이동, 상세에서 홈 복귀, 마일스톤·메달리스트 펼치기를 확인.
- 검토 시점: 전체 227경기, 선택 날짜 9월 9일 6경기. 계속 플레이하면 숫자는 달라진다.
- 홈·경기 상세·개인 페이지 순회 중 수집한 브라우저 pageerror는 없었다. 실제 휴대폰 Safari 및 화면 낭독기 검증은 하지 않았다.
- 스크린샷은 로컬 `.vercel/audit-*.png`에 보관했다. 자동화 전체 페이지 캡처에서 고정 하단 메뉴가 중간에 보이는 것은 캡처 특성이므로 별도 UI 오류로 판단하지 않았다.

## 개선 방향

‘마 좀 치나?’의 사투리, 친구 별명, MVP·걸배이 사진 연출을 중심으로 **4인 스쿼드의 경기 뒤풀이 화면**을 만든다. 첫 화면에서 오늘 결과를 이해하고, 재미있는 기록을 발견하고, 해당 경기로 들어가 근거를 확인할 수 있어야 한다.

## 홈의 정보 순서

390px 화면에서 ‘당일 게임’은 페이지 시작으로부터 **1,838px 아래**에 있었다. 첫 화면이 844px이므로 경기 전에 두 화면이 넘는 거리를 내려야 한다. 네 명의 누적 프로필과 커다란 MVP 카드가 먼저 나오고, 선택 날짜 통계와 전체 통계도 섞인다.

추천 순서:

1. 날짜 + 이날 전적 한 줄. 예: 검토 시점 기준 ‘6전 1승 5패 · 마지막 판 승리’.
2. 이날의 시상식 요약: 최고의 한 판 / 평소 대비 상승·하락. 세부 기준과 재생 버튼.
3. 해당 날짜 경기 목록. 승패·시간·네 명의 핵심 기록을 우선, 반복되는 조합 평가는 펼친 뒤 표시.
4. 네 명의 간단한 프로필 링크.
5. 누적 기록과 분석은 ‘우리 기록’ 구역으로 묶기.

모바일 하단 메뉴는 현재 스크롤 앵커다. 사용 중인 메뉴에 선택 상태를 표시하고 홈 이외의 페이지에서도 현재 위치를 알 수 있게 한다. 데스크톱에서도 날짜·경기·선수·기록으로 바로 이동하는 작은 메뉴가 있으면 긴 스크롤을 줄일 수 있다.

## 개인 페이지

- 네 명의 모바일 페이지 높이는 점검 시 약 3,366~4,942px. ‘의심 챔피언’이 여덟 개 이상 나열되는 사례가 있어 주력 챔피언 기록이 밀린다. 요약 2~3개와 ‘더 보기’로 줄인다.
- 챔피언 목록은 경기 수 내림차순인데 펼치기 문구는 ‘TOP3’라 점수 상위 세 개처럼 읽힌다. 기본값을 ‘많이 한 순’으로 명시하고 ‘점수순·승률순’, 챔피언 검색, 최소 경기 수 필터를 제공한다.
- 상단의 경기 수와 승률은 항상 함께 플레이하는 네 명에게 동일한 값이다. 개인의 평균점수, 최근 변화, 대표 챔피언, 보유 칭호를 더 크게 보여준다.
- ‘좀 치노 / 별론데?’의 경계는 50점이다. 승률 86%인 탈리야가 점수 48로 ‘별론데?’에 들어가는 사례가 있다. 승률과 기여도를 나란히 설명해 무엇에 대한 평가인지 분명히 한다.
- 추세 그래프의 점을 눌렀을 때 날짜·챔피언·승패·점수와 경기 링크를 제공한다. 현재 데스크톱에서는 넓은 카드 중앙의 작은 그래프로만 보인다.
- 추천 문장에 `Mage·Support`가 그대로 나온다. ‘뽑을 기회가 생기면 해볼 챔피언’이라는 ARAM 문맥과 한국어 설명으로 정리한다.

## 해설의 신뢰도

재미있는 문장은 유지하되, 화면에서 실제로 설명할 수 있는 사실에 붙여야 한다.

- ‘오늘 승패에 가장 큰 영향을 준 픽’은 증강 사용 결과의 단순 승패 집계다. ‘승리한 기록에서 자주 보인 증강’과 사용 횟수·승패를 보여주는 편이 정확하다.
- ‘탱커가 부족해서 한타를 열고 버티기 어려웠다’는 저장된 네 명의 역할 분류를 근거로 한다. ‘우리 4인 픽에는 탱커가 없었어요’처럼 관찰 사실을 표시하고 반복되는 문장은 요약한다.
- 최근 분석의 ‘킬보다 23.0개씩 앞선다’는 실제 코드에서 평균 어시스트 자체를 사용한다. 표시 문장의 수치 의미를 바로잡아야 한다. 관측하지 않은 교전 원인을 단정하는 표현도 줄인다.
- 메달 설명은 ‘최고 딜량’처럼만 쓰여 있지만 실제로는 상대 대비 기준을 충족해야 수상한다. ‘왜 받았나’를 눌러 기준과 해당 경기 수치를 보여준다.

## 재미 요소: 기존 기록으로 만들 수 있는 것

### 1. 오늘의 전적 영수증 — 효과가 가장 클 것으로 판단

날짜, 승패, 플레이 시간, 최고의 한 판, 상승·하락 주인공, 메달을 한 장으로 구성한다. ‘이미지 저장’과 ‘링크 복사’를 제공해 사용자가 단톡방에 공유할 수 있게 한다. 실제 전적 문장과 사투리 한 줄을 결합한다. 생성 후 미리보기에서 공유 범위를 확인할 수 있게 한다.

### 2. 시상식 다시 보기

현재 MVP·걸배이 사진 연출은 약 2초 후 사라지며 재생 버튼이 없다. 일간 시상 카드에서 다시 재생하고 닫기 버튼을 제공한다. 자동 연출 여부를 선택할 수 있게 하고, 이미 있는 움직임 줄이기 대응은 유지한다. 사진과 농담을 평상시 카드에서도 작게 이어 쓰면 서비스의 개성이 살아난다.

### 3. 타이틀 쟁탈전

이미 있는 마일스톤의 ‘2위와 1.4% 차’에 도전자 이름과 실제 격차를 붙인다. 횟수형 기록은 ‘어시왕까지 N개 차이’, 평균형 기록은 ‘평균 N점 차이’처럼 표현한다. 평균 기록에 ‘다음 한 판이면 탈환’ 같은 확정 예측은 하지 않는다. 주간/월간 조회를 추가하면 누적 1위가 고정되어도 새로운 경쟁이 생긴다.

### 4. 내 기록 경신·반등 카드

개인 최고 점수, 최다 어시, 최근 저점 이후 점수 상승 등 기존 경기 결과에서 확인되는 이벤트만 골라 표시한다. ‘항상 1등’ 이외의 사람도 등장할 수 있다. 각 카드에서 해당 경기와 이전 기록을 열어볼 수 있게 한다.

### 5. 챔피언 도감

개인별 플레이한 챔피언, 경기 수, 최고점, 첫 승을 묶어 도감처럼 탐색한다. 작은 표본에는 경기 수를 함께 표시한다. ARAM 특성상 정확히 같은 4챔피언 조합이 세 번 나와야 하는 현재 ‘최고 조합’은 227경기에서도 빈 카드였다. 반복해서 비어 있는 카드보다 도감이나 역할 구성별 기록이 실제 콘텐츠를 제공하기 쉽다.

## 추천 작업 순서

1. 모바일 카드·표, 색 대비, 한국어·시간 표기, 날짜 복귀를 먼저 수정한다.
2. 홈을 이날 결과 → 시상 요약 → 경기 순서로 재배치하고 전체 통계를 구분한다.
3. 시상식 다시 보기와 전적 영수증을 붙인다.
4. 타이틀 경쟁·기록 경신·도감은 앞선 화면이 안정된 뒤 추가한다.

점수 산식 변경, 아이템 수집, 외부 API 도입 없이 시작할 수 있다. 새로운 기능을 한꺼번에 늘리기보다 **이미 있는 재미를 잘 보이게 하고, 눌렀을 때 근거 경기까지 이어주는 것**이 첫 목표다.
